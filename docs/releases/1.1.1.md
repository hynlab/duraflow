# Duraflow 1.1.1

## Failure handling and bounded retries

Fixes the four defects reproduced in the independent 1.1.0 audit.

- **Catchable parallel failures (DF-AUDIT-01):** `gather` and `broadcast` group
  errors obey the existing 256 KiB payload and nesting limits. A fitting error is
  unchanged. Otherwise `causes` contains a deterministic prefix in member order,
  and `omitted_causes` reports the number of excluded failures. All original
  errors remain in their node records. A workflow can catch `TaskFailure` with
  code `GROUP_FAILURE` and execute compensation even when many members fail.
- **Replay recovery:** previously recorded oversized group summaries are bounded
  when reconstructed for replay, without rewriting committed history. This also
  works with subprocess replay. After upgrading engines and workflow workers,
  an operator can use audited `resume` on a run blocked by this specific defect.
  Arbitrary invalid individual task errors still fail payload validation.
- **Malformed workflow identities (DF-AUDIT-02):** the state owner validates key
  component types, workflow names, and nonempty instance IDs of at most 256
  characters before constructing topics. Invalid identities become protocol
  errors and follow the DLQ-then-ACK path. Database and transport failures remain
  retryable.
- **Safe exponential backoff (DF-AUDIT-03/04):** retry intervals are capped before
  a multiplication can exceed `max_delay`. Large finite multipliers no longer
  overflow, and slow-growing policies continue growing after attempt 31 until
  they reach their configured cap. Retry attempt limits are unchanged.

## Compatibility

Execution protocol 2 and PostgreSQL schema 4 / SQLite schema 3 are unchanged.
Already scheduled retry timestamps are retained; the corrected calculation applies
when the next retry is scheduled. Consumers of group errors must account for
`omitted_causes` instead of assuming `causes` is always exhaustive.

## Verification

See [1.1.1 verification](../qualification-1.1.1.md) for the executed checks and
native-service limitations. Regression coverage includes the exact payload limit
and one-byte overflow, large/deep metadata, real subprocess replay, existing
oversized histories, malformed identities, transient database failures, and
Memory/SQLite retries.
