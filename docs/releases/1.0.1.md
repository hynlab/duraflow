# Duraflow 1.0.1

Recovery and journal-correctness fixes, with expanded distributed qualification.

## Fixes

- Make outbox identity collisions atomic on Memory, SQLite, and PostgreSQL.
  Identical retained publications are idempotent and retain their delivery leases;
  conflicting publications roll back inbox, state, and outgoing intent together.
- Preserve JSON numeric wire representations in PostgreSQL message journals,
  including exponent-form floats and negative zero, to keep replay fingerprints
  and outgoing message identities stable.
- Retain malformed deliveries for redelivery if DLQ publication or acknowledgement
  fails, rather than leaving messages stranded in flight.
- Reject incomplete or invalid task-service contracts as protocol errors before
  business execution.
- Close native Pulsar consumers that finish subscribing after an awaiting operation
  is cancelled or times out, for both provisioning and active receive subscriptions.
- Give newly committed workflow publications and replay activations rollback-distinct
  identities. Stale replay responses from a discarded database timeline can no longer
  suppress a newly scheduled completion through a reused inbox identity. Committed
  outbox redelivery and business-task idempotency keys remain stable.
- Use untruncated process listings for test-owned process cleanup on Linux and macOS;
  long interpreter paths no longer prevent owned worker termination.

## Upgrade from 1.0.0

**Execution protocol remains 2.** PostgreSQL message-journal schema advances from
1 to **2**, using `JSON` instead of `JSONB` for state and outbox documents.
SQLite message-journal schema remains 1.

Stop DB-backed roles, initialize each workflow/task/tag journal with the updated
package, and restart the roles. Initialization upgrades PostgreSQL journals
transactionally under an advisory lock, retaining inbox identities, state, and
outbox owners/leases. Numeric representations already normalized by an older
JSONB journal cannot be reconstructed from the journal alone.

See [the schema-2 upgrade guide](https://github.com/hynlab/duraflow/blob/v1.0.1/guide/6_operations.md#postgresql-message-journal-schema-2).

## Distributed verification

New scenarios cover journal contracts on all three stores, generated histories,
publication/ACK/DLQ failures, deadlines and cancellation, replay divergence,
two independent engines/replay workers, 1/2/4 task workers, process commit boundaries,
database TCP partitions, PostgreSQL/Pulsar restart and pause, live stale-owner
fencing after topic unload, and physical WAL restore with separate journal timelines.

Local qualification included the full non-fault matrix on Python 3.12/3.13,
16 destructive recovery tests, and two 30-minute sustained workloads. The later
workload completed **1,656 workflows**, **3,312 accepted external effects**, and
**83 role restart events**, then drained the outbox. The measured overall
branch-aware coverage was **85.80%**. See the
[qualification report](https://github.com/hynlab/duraflow/blob/v1.0.1/docs/qualification-2026-10-08.md)
and [scenario catalog](https://github.com/hynlab/duraflow/blob/v1.0.1/docs/qualification.md).

PITR coverage includes operator-assisted replay of a known acknowledged signal;
it does not establish generic automatic reconciliation after arbitrary rollback.
Multi-host/quorum failover remains outside this standalone-service qualification.

## Install

```bash
python -m pip install --upgrade 'duraflow==1.0.1'
```

Python 3.12+ is required. PostgreSQL and Pulsar adapters remain bundled in the base
package. `make extended-check` and the manual sustained-qualification workflow
provide repeatable regression and load profiles.
